# 08 — التطوير والتحديث

## القاعدة: الإنتاج ما هو بيئة تجربة

```
فرع جديد → تطوير → اختبار في docker → مراجعة → نسخة احتياطية → نشر → تحقق
```

## سير العمل

```bash
# 1) فرع لكل تغيير
git checkout -b feature/<اسم-مختصر>

# 2) تحقق من الصياغة قبل أي شيء (كل الملفات)
for f in $(find . -name "*.php" -not -path "./.git/*"); do php -l "$f" | grep -v "No syntax errors"; done

# 3) اختبار حي في بيئة معزولة
docker compose up -d      # اللوحة على :8080 وراوتر وهمي على :8081

# 4) نشر
bash ops/backup.sh        # قبل النشر، إلزامي
git pull && bash ops/health-check.sh
```

## قواعد خاصة بهذا الكود (مهمة)

1. **`include/config.php` لا يُعدَّل يدويًا في الإنتاج** ولا يُدفع إلى git.
   التعديل يتم من واجهة اللوحة.
2. **لا تكسر صيغة `config.php`** — `include/readcfg.php` يعتمد على فواصل حرفية
   (`!`, `@|@`, `#|#`, `%`, `^`, `&`, `*`, `(`, `)`, `=`, `+`, `@!@`, `<|<`, `>|>`).
   أي تغيير في الصيغة يكسر كل الجلسات المحفوظة.
3. **بعد أي ترقية للوحة:** افتح كل User Profile واضغط Save — لتحديث سكربت
   `on-login` في الراوتر، وإلا تتوقف تقارير المبيعات.
4. **قوالب الكروت**: الصيغة الحديثة للـ QR هي `<?= $qrcode ?>` بدون وسم `<img>`.
5. **لا تضف قاعدة بيانات** إلا بقرار معماري واضح — التطبيق كله مبني على أن الراوتر
   هو مصدر الحقيقة.
6. **التوافق**: الكود مكتوب لـ PHP 7.x. قبل أي ترقية لـ PHP 8.x، اختبر في docker —
   الأخطاء مكتومة (`error_reporting(0)`) فالانهيار بيظهر كصفحة بيضاء لا كخطأ.

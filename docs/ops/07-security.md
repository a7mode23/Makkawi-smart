# 07 — الوضع الأمني والتحصين

نتيجة تدقيق فعلي لكود هذا المستودع بتاريخ 2026-09-15. مرتّبة حسب الخطورة.

---

## 🔴 1. كلمة مرور الأدمن الافتراضية مشحونة داخل المستودع

`include/config.php` فيه:
```php
$data['mikhmon'] = array ('1'=>'mikhmon<|<mikhmon','mikhmon>|>aWNlbA==');
```
القيمة `aWNlbA==` تفك إلى **`1234`**. يعني الافتراضي: **`mikhmon` / `1234`**،
وهي معروفة لأي شخص يعرف Mikhmon.

**الإجراء (قبل أي شيء آخر):**
1. غيّر كلمة المرور من اللوحة: Admin Settings.
2. تأكّد أن `include/config.php` على الإنتاج ما عاد فيه `aWNlbA==`.
3. لا ترفع `config.php` الخاص بالإنتاج إلى GitHub أبدًا.

## 🔴 2. `include/config.php` مرفوع في Git ويحمل أسرارًا

الملف متعقّب في المستودع. أول ما تضيف راوتر حقيقي من اللوحة، الملف على السيرفر
يصير يحتوي IP ومستخدم وكلمة مرور الراوتر. أي `git add -A` ثم `push` = تسريب.

**الإجراء على السيرفر (مرة واحدة):**
```bash
git update-index --skip-worktree include/config.php
```
هذا يمنع git من التقاط تعديلاتك المحلية. وقبل أي commit من السيرفر:
```bash
git diff --cached -- include/config.php     # لازم يطلع فاضي
```

## 🟠 3. "التشفير" ليس تشفيرًا

`encrypt()/decrypt()` في `lib/routeros_api.class.php:440` = إزاحة أحرف بمفتاح ثابت
`128` + Base64. قابلة للفك فورًا بدون أي مفتاح سرّي.

**الخلاصة العملية:** كلمات مرور الراوترات في `config.php` تُعامل كأنها **مكتوبة
بالنص الصريح**. لذلك:
- صلاحيات الملف: `chmod 640 include/config.php` ومالكه مستخدم الويب فقط.
- أنشئ في الراوتر **مستخدم API مخصص للوحة** بصلاحيات محدودة، بدل `admin` الكامل:
  ```
  /user group add name=mikhmon policy=api,read,write,test,winbox
  /user add name=mikhmon-api group=mikhmon password=<قوية> address=<IP السيرفر>
  ```
  وحصر `address` على IP السيرفر يمنع استخدام البيانات من مكان تاني حتى لو تسرّبت.

## 🟠 4. لوحة الإدارة مكشوفة على الإنترنت

اللوحة تتحكم في الراوتر بالكامل (بما فيها **إعادة تشغيل وإطفاء** الراوتر عبر
`process/reboot.php` و `process/shutdown.php`). لو هي مفتوحة على IP عام:

**التحصين (الأقوى أولًا):**
1. اجعلها خلف VPN أو شبكة داخلية فقط.
2. إن تعذّر: HTTP Basic Auth إضافي على nginx + حصر `allow`/`deny` بـ IP.
3. HTTPS إلزامي (بدونه كلمة مرور اللوحة تمشي بالنص الصريح).
4. حدّد معدل المحاولات (rate limit) على `admin.php` لمنع تخمين كلمة المرور —
   الكود **ليس فيه أي حد لعدد المحاولات**.

مثال nginx:
```nginx
location = /admin.php {
    allow 10.0.0.0/8; allow <IP-المكتب>; deny all;
    limit_req zone=login burst=5 nodelay;
    try_files $uri =404; include fastcgi_params; fastcgi_pass php-fpm;
}
```

## 🟠 5. صفحة حالة الكرت عامة بالتصميم

`status/status.php` لا تتحقق من الجلسة (عشان الزبون يفحص كرته)، لكنها **تفتح
اتصالًا بالراوتر ببيانات الأدمن** وتقبل `?session=` و `?name=` من العميل.

**الأثر:** من يعرف اسم الجلسة يقدر يستعلم عن أي اسم مستخدم.
**التحصين:** اجعل اسم الجلسة غير قابل للتخمين، وضع rate limit على هذا المسار،
ولا تكشف بقية اللوحة على نفس الـ vhost لو ما في داعي.

## 🟡 6. إخفاء كل الأخطاء (`error_reporting(0)`)

موجود في كل ملف تقريبًا. يخفي الاستغلال والخلل معًا.
**التحصين:** لا تفعّل `display_errors` على الإنتاج، لكن **فعّل `log_errors`**
مع `error_log` مخصص، عشان يكون عندنا أثر نقرأه وقت الحادثة.

## 🟡 7. مدخلات `$_GET` تُستخدم مباشرة

`index.php` يقرأ عشرات المتغيرات من `$_GET` ويمررها لأوامر RouterOS API.
لا يوجد SQL (لا توجد قاعدة بيانات) لكن يوجد تمرير مباشر لأوامر الراوتر ولمسارات
الملفات (`remove-logo` يستدعي `unlink()` على قيمة من `$_GET`).

**التحصين:** لأن اللوحة محمية بالجلسة، الخطر يقتصر على مستخدم مسجّل دخول —
وهذا سبب إضافي لتقييد الوصول للوحة (بند 4) وتغيير كلمة المرور الافتراضية (بند 1).

## 🟡 8. صلاحيات الكتابة على ملفات PHP

التطبيق يكتب في `include/config.php` و `include/lang.php` و `include/theme.php`
و `voucher/template*.php` وقت التشغيل. أي ثغرة رفع ملفات تتحول لتنفيذ كود.

**التحصين:**
```bash
find . -type f -name "*.php" -exec chmod 644 {} \;
find . -type d -exec chmod 755 {} \;
chmod 640 include/config.php
chown -R root:www-data . && chown www-data include/config.php include/lang.php include/theme.php voucher/template*.php img
```
ولا تستخدم `chmod -R 777` نهائيًا (السطر الموجود في `.profile` بقايا نشر قديم
لمجلد `Storage` غير موجود أصلاً — يُتجاهل).

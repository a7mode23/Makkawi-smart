# 04 — الصيانة الدورية

الهدف: ما نكتشف المشكلة من الزبون. كل بند هنا فيه **أمر قابل للتنفيذ** ومعيار نجاح.

---

## يوميًا (دقيقتان)

```bash
bash ops/health-check.sh
```
معيار النجاح: كل الفحوص `OK` أو `SKIP`. أي `FAIL` → روح لـ [03-incidents.md](03-incidents.md).

زيادة على الفحص الآلي، نظرة سريعة على اللوحة:
- [ ] Dashboard يفتح ويعرض Uptime للراوتر
- [ ] عدد الـ Hotspot Active منطقي مقارنة بالأمس
- [ ] التقرير اليومي (Report) فيه عمليات اليوم

## أسبوعيًا (10 دقائق)

- [ ] `bash ops/backup.sh` + **تأكيد أن النسخة انتقلت لمكان خارج السيرفر**
- [ ] نسخة من الراوتر نفسه:
  ```
  /system backup save name=wasel-weekly
  /export file=wasel-weekly            # نسخة نصية قابلة للقراءة والمقارنة
  ```
  ثم نزّل الملفين من `/file` واحفظهم خارج الراوتر.
- [ ] مساحة القرص على السيرفر `< 80%` — `df -h`
- [ ] سجل الأخطاء ما فيه تكرار جديد — `tail -100 /var/log/nginx/error.log`
- [ ] المستخدمون المنتهون: نظّفهم من اللوحة (User List ← فلتر expired)
- [ ] راجع [05-renewals.md](05-renewals.md) — أي شيء بينتهي خلال 30 يوم؟

## شهريًا (30 دقيقة)

- [ ] **تحديثات الأمان للنظام**
  ```bash
  apt update && apt list --upgradable      # Debian/Ubuntu
  apt upgrade                              # في نافذة الصيانة فقط
  ```
- [ ] فحص إصدار PHP مدعوم أمنيًا (الموصى به: 7.4 أو 8.0 لهذا التطبيق)
- [ ] مراجعة `include/config.php`: هل فيه جلسات راوتر قديمة/ميتة؟ احذفها
- [ ] مراجعة مستخدمي الراوتر: `/user print` — أي حساب ما بينستخدم يتعطّل
- [ ] **اختبار استرجاع فعلي**: استرجع آخر نسخة في بيئة docker وتأكد اللوحة تشتغل
      (`docker compose up -d` ثم `bash ops/restore.sh <backup.tar.gz>` على نسخة اختبارية)
- [ ] تحديث [02-inventory.md](02-inventory.md) لو أي شيء اتغيّر
- [ ] مراجعة سريعة لبنود [07-security.md](07-security.md)

## ربع سنويًا

- [ ] مراجعة إصدار RouterOS — ترقية **فقط** في نافذة صيانة ومع نسخة احتياطية جاهزة
- [ ] مراجعة سعة الترخيص مقابل عدد المستخدمين الفعلي
- [ ] مراجعة الأسعار/الباقات في البروفايلات مع المالك
- [ ] تنظيف سكربتات التقارير القديمة جدًا من الراوتر **بعد** تصديرها ونسخها

---

## قواعد نافذة الصيانة

1. أي عمل يقطع الخدمة → **في نافذة الصيانة المتفق عليها فقط** (راجع الجرد §ز).
2. قبل أي ترقية: نسخة السيرفر + نسخة الراوتر + خطة رجوع مكتوبة.
3. تغيير واحد في المرة. لو وقع عطل، نعرف السبب فورًا.
4. بعد كل صيانة: `bash ops/health-check.sh` + تسجيل السطر في السجل أدناه.

# الاستجابة لعطل — منصة واصل

## 1. صنّف قبل ما تلمس أي شيء

| المستوى | الوصف | السرعة |
|---|---|---|
| P1 | الزبائن بدون إنترنت | فورًا |
| P2 | اللوحة واقفة، الإنترنت شغال | خلال ساعة |
| P3 | ميزة واحدة معطلة | نفس اليوم |
| P4 | بطء أو خلل تجميلي | مجدول |

اسأل نفسك السؤال الفاصل:
```
إنترنت الزبائن واقف؟ → المشكلة في الراوتر/المزوّد (اللوحة بريئة)
اللوحة وحدها واقفة؟  → المشكلة في السيرفر أو مسار الشبكة (الزبائن بخير)
```

## 2. اجمع الأدلة (لا تصلح قبل ما تفهم)

```bash
bash ops/health-check.sh
tail -80 /var/log/nginx/error.log 2>/dev/null
tail -80 /var/log/php*-fpm.log 2>/dev/null
systemctl status nginx php*-fpm 2>/dev/null | head -20
```

## 3. طابِق الحالة

افتح `docs/ops/03-incidents.md` وابحث عن العَرَض:
صفحة بيضاء · Mikhmon not connected · الزبائن ما بيدخلوا · التقارير اختفت ·
الكروت ما بتطبع · بطء · تعذّر الدخول للوحة.

**لو العَرَض غير مذكور:** شخّص من `01-architecture.md`، وبعد الحل **أضف الحالة
الجديدة للكتيّب** — هذا جزء إلزامي من المهمة.

## 4. أصلح بأمان

- نسخة احتياطية أولًا: `bash ops/backup.sh` (إلا لو السيرفر نفسه واقف)
- أصغر تغيير ممكن، واحد في المرة
- ⛔ لا تعيد تشغيل الراوتر، ولا تحذف مستخدمين/تقارير — **إلا بإذن صريح**
- بعد كل خطوة: هل اتغيّر العَرَض؟ لو لا، ارجع عنها قبل ما تجرّب غيرها

## 5. تحقّق وأغلق

```bash
bash ops/health-check.sh
```
ثم اختبر المسار المتأثر فعليًا (دخول اللوحة، اتصال الراوتر، طباعة كرت، دخول زبون).

## 6. وثّق — إلزامي

أضف صفًا في جدول نهاية `docs/ops/03-incidents.md`:
`التاريخ | العَرَض | السبب الجذري | الإصلاح | الوقاية`
